# Supabase Auth for hosted staff access

Status: accepted (the mandatory-TOTP clause superseded by ADR-0006; the "password reset … revokes every session" behavior below now applies to owner-issued resets only — a member's self-service password change revokes no sessions, per the ticket-82 review amendment recorded in ADR-0006)

Supabase Auth owns staff passwords, sessions, and mandatory TOTP factors, while the application database owns usernames, staff membership, status, and owner/staff/editor permissions. Owners create staff/editor accounts with an initial password; there is no public signup, invitation email, or email-based recovery. A password reset preserves the enrolled factor and revokes every session, while a separate MFA reset removes the factor, revokes every session, and forces reenrollment. Synthetic internal email identifiers satisfy Supabase Auth's email/password interface but are never shown or used for delivery.

This supersedes ADR-0001's Better Auth and fully offline login choice: localhost uses the dedicated hosted test project, protected requests verify both the current Supabase session and the linked active staff account, and visitor sessions remain separate. Chat escalation remains an in-dashboard sound/attention event rather than outbound email. The migration starts with fresh staff identities and configuration-only data transfer so the original database stays intact.
