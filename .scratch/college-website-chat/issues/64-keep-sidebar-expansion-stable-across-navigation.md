# 64: Keep the expanded sidebar stable across dashboard navigation

**Status:** ready-for-human
**Category:** bug
**Priority:** P2
**Related:** [52: Collapsible sidebar](52-collapsible-sidebar-navigation.md), [57: Icon sidebar and hover labels](57-icon-sidebar-with-individual-hover-labels.md), [58: Full-height sidebar](58-full-height-reference-sidebar.md)

## Agent Brief

**Summary:** When staff expand the dashboard sidebar and choose another destination, the sidebar must stay visibly expanded throughout navigation instead of briefly collapsing and expanding again.

**Current behavior:** The sidebar's explicit expanded choice is saved, but each dashboard page mounts a new header with a collapsed initial state and restores the saved choice only after mounting. Moving between sidebar destinations therefore shows a collapse-then-expand flash.

**Desired behavior:** The sidebar's current expanded/collapsed state remains continuous while navigating among dashboard pages, including back and forward navigation. The chosen destination changes and the active icon updates; the rail's width and labels do not momentarily reset. Explicit expand/collapse still works and the saved choice remains available on later visits. Preserve the current icon-only default when no preference has been saved.

**Key interfaces:** The shared dashboard sidebar owns the expansion choice. Dashboard page navigation must not temporarily render a contradictory sidebar state. Keep the current destination links, role filtering, mobile drawer, and individual compact hover/focus labels.

**Acceptance criteria:**

- [ ] Expand the desktop sidebar, then navigate among Conversations, History, Visitor emails, Analytics, Answers, Staff, and Email alerts where permitted. The sidebar stays expanded on every route transition without a visible width or label flash.
- [ ] Browser back/forward navigation also preserves the current expanded/collapsed state without an intermediate reset.
- [ ] A user who explicitly collapses the sidebar stays collapsed while navigating; a user who explicitly expands it stays expanded. Reloading retains the existing saved-choice behavior, and a user with no saved choice still starts in the compact icon-only state.
- [ ] Active-route indication, sign out, compact one-at-a-time hover/focus callouts, keyboard operation, and the narrow-screen drawer still work.
- [ ] Verify the behavior in the real browser with an expanded sidebar across at least two dashboard destinations; a snapshot taken during navigation must not show the compact rail before the expanded state returns.

**Out of scope:** Changing sidebar destinations, visual styling, mobile drawer design, dashboard page content, or the conversation desk's own scrolling behavior (ticket 65).
