# 61: Bring active visitor and staff chat updates close to one second

**Status:** ready-for-human

**What to build:** Make messages from the other person appear in about one second while a visitor chat or the staff conversation desk is active. Keep the deterministic bot-answer path intact; local measurements show it already returns an approved answer in the same send response.

- [x] A visitor with the chat **open** and an active session checks for staff messages about every **1 second**. Opening a saved chat fetches once immediately. A visitor with the panel **closed** stays on the pre-ticket 3-second cadence; a fresh visitor with no conversation session makes no history requests. Do not reintroduce ticket 59's 30-second closed cadence.
- [x] The staff **active conversation desk** checks for incoming visitor messages and new waiting conversations about every **1 second** while its browser tab is visible. History views keep the existing 3-second cadence. Hidden staff tabs continue to pause refreshes and catch up when visible again.
- [x] Avoid stacking overlapping visitor history requests or staff refreshes if a response takes longer than a tick. Stale visitor responses still cannot repaint a cleared or replaced chat. Keep the current authorization and missed-message recovery.
- [x] Bot answers continue to appear from the send request without waiting for a poll. Do not alter answer matching, publishing, schemas, or API contracts to chase a latency problem that was not observed.
- [x] Measure visitor-to-staff and staff-to-visitor message appearance in the real local UI, plus the local bot-answer round trip. Verify visible/open chat updates are near one second under normal local conditions, the closed panel does not poll faster than before, and hidden staff tabs do not poll. Record the request-rate tradeoff: an open chat at 1 second makes up to three times as many checks as its prior 3-second cadence.

## Context

The visitor widget currently polls full history every 3 seconds for any saved session in `src/app/widget/frame/page.tsx`. The staff conversation desk mounts `AutoRefresh` from `src/app/dashboard/conversations/[id]/auto-refresh.tsx`, whose default interval is also 3 seconds. The visitor's own send is optimistic and a bot answer comes back in the POST response; five local approved-answer POSTs measured 89, 93, 116, 165, and 187 ms on 2026-11-06. Those are local development timings, not production latency guarantees.

Ticket 59's cost optimization was reverted at the user's request. This ticket prioritizes active-chat responsiveness while leaving the old closed-panel request behavior in place. The user said approximately one-second updates are sufficient; a push transport is unnecessary for this ticket.
