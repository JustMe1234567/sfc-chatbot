# 19: Owner bootstrap must target the active database store

**Status:** ready-for-human  
**Priority:** P1 — blocker for browser testing
**Found by:** pre-testing audit 2026-10-30 (docs/config pass; verified directly)

**What to build:** `scripts/bootstrap-owner.ts` hardwires SQLite: it calls `openDatabase(appDbPath())` with `NodeSqliteDialect` and never reads `DATABASE_URL` (`scripts/bootstrap-owner.ts:29-38`). An operator following the README against a production environment gets "Owner account ready" while the owner account is written into a local `chatbot.db`, and the Supabase database has no owner. `docs/deployment.md` documents no owner-creation path for the Postgres deployment at all.

- [ ] When `DATABASE_URL` (or `POSTGRES_URL`) is set, bootstrap provisions the owner through the Postgres auth path (same `createAuth` + `provisionStaffMember` flow the app uses, over `openPostgres`).
- [ ] When neither is set, it keeps working on SQLite for local development and says so in its output.
- [ ] Bootstrap never silently writes to a store other than the one the running app would use: its final message names which store it targeted.
- [ ] `docs/deployment.md` gains a production owner-bootstrap step matching the script's behavior.
