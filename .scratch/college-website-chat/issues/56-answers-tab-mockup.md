**What to build:** Evolve the Answers tab (redesigned in ticket 55) to match the approved mockup exactly. The three-tab structure, in-place switching, client-side search, expand/collapse cards, and all save flows already exist and stay — this ticket is a presentation-layer refinement of that page plus one new client-side control (a status filter). Scope is the Answers tab only; no backend, API, schema, or matching-logic changes.

## Header

- [ ] The New answer action becomes a **filled primary blue button with a plus icon**, labelled **New Answer** (today it renders as the outline secondary button with plain text). It stays in the top-right of the heading row.

## Search and filter row

- [ ] The search input gains a **magnifying-glass icon** and the placeholder **"Search answers…"**.
- [ ] A **status filter dropdown** sits to the right of the search input: **All statuses** (default), **Published**, **Draft**. It composes with the text search (both apply, AND) and, like search, filters the already-loaded rules client-side — no requests.
- [ ] Below the row: a live **result count** on the left ("N answers", reflecting the active filters — 0 renders the existing no-match empty state) and an informative **"Sorted by current order"** label with a small sort glyph on the right. The label is informational only — no reordering control is implied.

## Answer cards

- [ ] Each card gains a **left icon tile**: a rounded square in the soft blue tint carrying one blue stroke icon per rule. Icons are chosen by a **deterministic client-side keyword map over the topic** (e.g. admissions/visit → people; fees/tuition/payment → coins; scholarship/financial aid → graduation cap; library → book; parking → car; anything else → a document fallback). Presentation only — no editor field, no schema or API change. Every icon is decorative (aria-hidden); the topic text beside it carries the meaning.
- [ ] The status badge becomes a **green pill with a check mark and title-case "Published"**; the draft pill keeps its neutral treatment with visible text (color never works alone, matching the dashboard's chip family).
- [ ] Card **meta rows use small stroke icons** before each item: person (publisher), calendar (reviewed date), speech bubble (phrase count), funnel (keyword conditions), chain link (college page link).
- [ ] **Collapsed cards** show: icon tile, title + status badge, the answer text truncated with a **single-line ellipsis** (the mockup's treatment — replacing ticket 55's two-line clamp), and a meta row with phrase count, keyword-condition count, and the college-page-link indicator (each with its icon, dot-separated as today).
- [ ] **Expanded cards** show: the full answer, a divider, then a meta row with publisher, reviewed date, and phrase count — with the **Edit** button (outline style, blue text, pencil icon) right-aligned on that row. The expand/collapse chevron stays.
- [ ] Interaction is unchanged: one keyboard-operable toggle per card announcing `aria-expanded`, collapsed bodies inert, Edit navigating to the rule editor.

## Constraints

- Tabs, Handoff Phrases, and Welcome Message tabs are untouched.
- Reuse the dashboard's existing tokens, chip family, and stroke-icon style (hand-authored inline SVG on the 24-grid, like the sidebar marks). No new dependencies.
- Keyboard accessibility and accessible names survive everywhere: the status filter is a labelled select, badges and counts keep visible text, icon-only decorations are aria-hidden.
- Responsive behavior preserved: the filter drops below the search on narrow screens, cards keep readable padding, no horizontal overflow.
