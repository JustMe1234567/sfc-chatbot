# 68: Fix Postgres test seeds that omit the NOT NULL last_activity_at column

**Status:** ready-for-agent

**Priority:** P3

**Related:** [50: Notifications pagination](50-*), [51: History delete](51-*), [Postgres parity docs](../../docs/deployment.md)

## Problem

Five tests fail when the suite runs against Postgres
(`CHATBOT_TEST_POSTGRES_URL=… npm test`), all with the same cause:

```
PostgresError: null value in column "last_activity_at" of relation
"conversations" violates not-null constraint
```

The Postgres schema has had `conversations.last_activity_at TEXT NOT NULL`
since `migrations/postgres/0001_auth_and_chat.sql`, but two test files seed
conversations with raw SQL INSERTs that name only `id, state, created_at`:

- `tests/history-delete.test.ts` — `seedConversation()` (5 failures across
  its four tests' setups)
- `tests/notifications-pagination.test.ts` — its conversation seeding

SQLite tolerates the missing column (nullable there), so the SQLite suite
stays green and the breakage only shows in Postgres mode. Confirmed
pre-existing on 2026-11-11 while certifying ticket 66: both files are
untouched by that ticket's diff, and the schema column predates them.
