# Pre-testing audit — 2026-10-30

**Scope:** the entire codebase on `main` at `76b9e3c` (all 18 tickets), audited statically before the human/browser testing phase. Working tree clean apart from `.scratch/` artifacts. Runtime/browsery verification is deliberately excluded — it is the next phase.

**Method:** five parallel read-only review passes (security, spec-correctness, code health, accessibility, docs/config/infra), each returning findings with file:line evidence; every load-bearing finding was then re-verified directly against the code before being accepted here. Mechanical evidence gathered alongside. Findings are filed as issues **19–34** in `issues/`; the mapping is in the index below.

## Verdict

**No P0 or P1 security findings.** The core authorization model is genuinely solid: visitor credentials are 256-bit random tokens stored only as SHA-256 and every conversation endpoint re-derives authorization from the token hash (mismatch → 404, no existence leak); return links are hashed, single-use, expiring; Better Auth has sign-up disabled, TOTP enforced server-side via `requireStaff` on every staff route; disable/reset revoke sessions and release claims; no XSS surface (no `dangerouslySetInnerHTML` anywhere), no raw-SQL interpolation; secrets stay server-side and `.env`/`*.db` are untracked.

The spec-correctness pass found **all 37 user stories implemented with the named testing-decision flows present and asserting** (each verified by test name), and Out-of-Scope holds (no AI API, no scraping, English-only, no attachments).

What the audit did find: **one P1 and eight P2s that gate the testing phase** (issues 19–27), plus queued polish (28–34). The single P1 is a deployment-correctness trap, not an exploit.

## Blockers — fix before browser testing (issues 19–27)

1. **Issue 19 (P1) — `bootstrap-owner.ts` is SQLite-only.** It hardwires `openDatabase(appDbPath())` + `NodeSqliteDialect` and never reads `DATABASE_URL` (verified: `scripts/bootstrap-owner.ts:29-38`). An operator following the README against a production env gets "Owner account ready" while writing the owner into a local `chatbot.db`. `docs/deployment.md` documents no Postgres owner-creation path at all.
2. **Issue 20 (P2, security) — rate limiting keys on the first `X-Forwarded-For` entry** (`src/api/visitor.ts:39`, verified). On any proxy that *appends*, clients rotate spoofed IPs to bypass every public limiter. Ticket 01 explicitly parked "production x-forwarded-for handling" on ticket 11; ticket 11 never picked it up (verified in both files). Spec requires abuse limits "enforced on the server."
3. **Issue 21 (P2, security) — no `frame-ancestors`/`X-Frame-Options` on dashboard routes.** `next.config.ts` sets no headers (verified) and no middleware exists; a malicious page can iframe the dashboard and clickjack staff actions (the app's own Origin rides inside the frame, so `sameOriginGuard` passes). Restrict `/dashboard/*` to `'self'` while keeping `/widget/frame` embeddable.
4. **Issue 22 (P2) — SQLite fallback fails slowly on serverless.** Without `DATABASE_URL`, `getChatbotService()` opens `repoRoot()/chatbot.db` (verified: `src/db/service.ts:89-94`, `src/config.ts:24-25`, `src/paths.ts`) — on Vercel's read-only FS that is a runtime crash with a confusing path, not a clear configuration error. Production should fail fast with a message naming the missing var.
5. **Issue 23 (P2, tracker) — ticket 11's recorded claims don't match reality.** Its criterion 5 (`[x]`) bundles "A Vercel preview verifies WordPress embedding and browser flows" which its own comment defers to the human step (verified: issues/11 line 13); its comment claims "origin checks … on public POSTs" but only `/api/v1/presence` calls `sameOriginGuard` (verified by grep); and the parked XFF item vanished from its scope (now issue 20). The tracker should tell the truth before ticket 11's human pass.
6. **Issue 24 (P2, security) — rate limiters are per-process in-memory maps** (`src/domain/limits.ts`). On Vercel each instance counts separately and cold starts reset them, so the effective limit is `limit × instances`. Needs a shared-store limiter (Postgres-backed counters are the natural fit) or an accepted, documented residual-risk decision.
7. **Issue 25 (P2, a11y) — handoff/claim/email states are never announced to screen readers.** The "College staff will reply…", "A college staff member has joined…", and email-capture blocks render *outside* the transcript's `role="log" aria-live="polite"` region (verified: `src/app/widget/frame/page.tsx:592-650`). The service's core event — a human took over — passes silently. Story 3.
8. **Issue 26 (P2, a11y) — no usable focus on widget open.** `openFrame()` never focuses inside the iframe; the click handler calls `frame.contentWindow?.focus()` which lands on the frame's `<body>` because the inner `autofocus` ran while the iframe was `hidden` (verified: `src/widget/loader.ts:80-118`, `frame/page.tsx:294-296`). Keyboard users re-Tab from the top every open, starting from an unpredictable point.
9. **Issue 27 (P2, a11y) — sub-24px touch targets** in the widget: close ~28px, email-decline ~15px, clear-conversation ~20px, save/confirm ~26px (`frame.module.css`, verified by the pass with line cites). Story 2 (mobile/touch usability) and WCAG 2.5.8.

## Queued — filed, non-gating (issues 28–34)

- **28** dashboard a11y: staff transcript has no live region (SR staff must poll manually); analytics period switch is an incomplete ARIA tabs pattern (no `tabpanel`/arrow keys).
- **29** widget a11y polish: new-tab links without warning, error uses polite `status` where `alert` fits, missing `autocomplete="email"`, no skip link + single shared document title, hidden scrollbar on the topics strip, Escape closes the widget while the clear-conversation confirm is open.
- **30** origin hardening: `sameOriginGuard` accepts a missing `Origin` header (`src/api/staff.ts:78-82`); public POSTs other than presence have no origin check (bearer-token model makes CSRF largely inapplicable — the decision should be recorded and, where sensible, enforced).
- **31** env documentation: no `.env.example` despite `.gitignore` un-ignoring it; undocumented optional vars (`POSTGRES_URL`, `PG_PREPARE`, `PG_POOL_MAX`, `PG_AUTH_POOL_MAX`, `CHATBOT_MAIL_TRANSPORT`, `NEXT_PUBLIC_CHATBOT_BASE_URL`).
- **32** infra/docs polish: widget cache-busting is manual (`build-widget.ts` overwrites the same `v1.js`, plugin enqueues `$ver = null`); migration numbering story lives nowhere (SQLite jumps 0008→0010 while `migrations/postgres/0001` claims to mirror a nonexistent 0009); stale "Build ticket 02 next" in `handoff-zcode.md`; duplicated `## Comments` blocks in tickets 13/14/16; `twoFactor` column defaults differ between dialects.
- **33** health refactor: `widget/frame/page.tsx` is a 765-line component owning six concerns; the staff fetch→`router.refresh()` error shape repeats ~8× across dashboard clients; the messages route's choice/text branches re-state the same preflight; four screenshot scripts duplicate the sign-in driver.
- **34** health backlog: bare `3000` poll literal and inlined 24h math; brand `#1d4e89` hardcoded in CSS modules (the loader's copy is a documented self-containment requirement — the CSS copies are not); stale 160ms/180ms comment in `loader.ts`; `DeskItem.state` weakens the state union to `string`; unwired `scripts/dump-auth-schema.ts`; ~39 unconsumed exports; unexpected store errors surface as Next's default HTML 500 instead of JSON.

- **Security:** visitor credential handling and per-conversation authorization, return-link redemption (hashed, single-use, transactional), staff auth lifecycle (invite-only, TOTP-enforced, revocation on disable/reset), secret hygiene, XSS/SQLi posture, analytics identifier hashing + rotation, retention purge scope, constant-time maintenance-secret compare.

- **Accessibility:** loader wiring (launcher/iframe/Escape/focus-return), `role="log"` transcript with srOnly-labeled composer, visible focus rings everywhere (no `outline: none`), color paired with text for state cues, `prefers-reduced-motion` honored across all three surfaces, no determinable AA contrast violations.
